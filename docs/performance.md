# Performance Benchmarking & Bundle Breakdown

This document provides instructions for evaluating rendering performance, main-thread responsiveness, and code-splitting efficiency across the **Enterprise Executive BI Dashboard**.

---

## ⚡ Multithreaded Web Worker Profiling Procedure

To demonstrate the specific main-thread blocking (UI jank) problem solved by offloading transaction calculations to an ES Web Worker, use the built-in feature flag `VITE_DISABLE_WORKER`.

### Step-by-Step Chrome DevTools Profiling

1. **Standard Worker Mode (Default - Enabled)**:
   - Start the development server normally: `npm run dev`.
   - Open Chrome DevTools (`F12`) and navigate to the **Performance** tab.
   - Click **Record** (`Ctrl + E`).
   - Interact with the dashboard by switching year/month filters rapidly across multi-year data.
   - Stop recording and observe the **Main Thread** timeline. Notice that frame rate stays smooth (60 FPS) and total blocking time (TBT) is near zero because calculations run in `dataWorker.ts`.

2. **Synchronous Main-Thread Fallback Mode (Worker Disabled)**:
   - Restart the server with the disable flag:
     ```bash
     VITE_DISABLE_WORKER=true npm run dev
     ```
   - Open Chrome DevTools Performance tab and click **Record**.
   - Perform the exact same filter interactions.
   - Stop recording and compare the main thread task duration and long tasks (red corner flags).
